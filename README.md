# Pirogram

Готовый стартовый проект мессенджера под телефон: тёмная тема, PWA, регистрация по логину и паролю, чаты, фото/видео в сообщениях, push-уведомления и базовый слой звонков без LiveKit/Supabase/SMS.

## Что изменено в этой версии

- Убран вход по номеру телефона.
- Убраны SMS-провайдеры и проверка номера.
- Вход и регистрация работают по `логин + пароль, плюс публичный @username для поиска`.
- Убраны LiveKit/Supabase realtime-зависимости.
- Сообщения обновляются через polling API, поэтому проект можно держать на Vercel без WebSocket-сервера.
- Фото и видео сохраняются прямо в сообщении как Data URL. Это удобно для версии без отдельного storage-провайдера, но лимит файла ограничен 3.5 МБ.

## Важно про базу данных

Для реального сайта на хостинге всё равно нужна база данных `DATABASE_URL`. Хостинг хранит файлы сайта, но не должен хранить пользователей, пароли и переписки в памяти. Проект использует Prisma + PostgreSQL.

## Локальный запуск

```bash
npm install
cp .env.example .env
```

Заполните `.env`:

```env
DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/pirogram?sslmode=require"
JWT_SECRET="очень_длинный_секрет_минимум_32_символа"
NEXT_PUBLIC_APP_URL="http://localhost:3000"
```

Создайте таблицы и запустите:

```bash
npx prisma migrate dev
npm run dev
```

Откройте `http://localhost:3000`.

## Деплой на Vercel

1. Загрузите все файлы проекта в GitHub репозиторий.
2. Импортируйте репозиторий в Vercel.
3. В `Project Settings → Environment Variables` добавьте:
   - `DATABASE_URL`
   - `JWT_SECRET`
   - `NEXT_PUBLIC_APP_URL`
   - `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY`, если нужны push-уведомления.
4. Деплойте проект.

Команда `npm run build` автоматически выполнит `prisma generate`, `prisma migrate deploy` и `next build`.

## Push-уведомления

Сгенерируйте ключи:

```bash
npm run push:keys
```

Затем добавьте их в `.env` и в Vercel:

```env
VAPID_PUBLIC_KEY="..."
VAPID_PRIVATE_KEY="..."
VAPID_SUBJECT="mailto:admin@example.com"
```

На iPhone push работает только после добавления сайта на экран Домой и выдачи разрешения на уведомления. На Android браузер предложит установку PWA или пункт будет в меню браузера.

## Звонки

В проекте есть серверная модель звонков и API `/api/calls`: создание звонка, принятие, завершение, уведомление участникам. Это сделано без LiveKit/Supabase. Для стабильных аудио/видео звонков через разные сети обычно нужен STUN/TURN. В `.env.example` оставлен необязательный `NEXT_PUBLIC_STUN_URL`, но по умолчанию он пустой.

## Ограничения версии без отдельных провайдеров

- Нет WebSocket realtime-сервера: используется polling каждые ~2.2 секунды.
- Фото/видео хранятся в базе как Data URL, поэтому файл ограничен 3.5 МБ.
- Для больших видео и большого количества пользователей позже лучше вынести медиа в S3/R2/Supabase Storage, но в этой версии это не требуется.

## Безопасность в этой версии

- Пароли хэшируются через bcrypt.
- Сессия хранится в httpOnly cookie.
- JWT проверяется middleware.
- Есть rate-limit на вход и регистрацию.
- API проверяет членство пользователя в чате.
- Валидация входящих данных через Zod.
- Базовые security headers в `next.config.ts`.


## Логин, ник и @username

В этой версии аккаунт хранит три разных поля:

- `displayName` — ник/имя, которое видно в чате. Его можно сделать красивым и русским.
- `login` — личный логин для входа. Его не показываем в поиске другим людям.
- `username` — публичный уникальный `@username`. По нему пользователи находят друг друга и открывают личный диалог.

В поиске чата вводите `@username` или часть ника. При нажатии на найденного пользователя Pirogram создаёт личный чат или открывает уже существующий.
